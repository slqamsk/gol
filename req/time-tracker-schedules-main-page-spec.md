## Требования к странице дневного трекера (`time-tracker.html`)

Имя файла документа: `time-tracker-schedules-main-page-spec.md`

### 1. Назначение

Страница позволяет:
- Отслеживать активности пользователя в течение дня с визуализацией на временной шкале.
- Создавать, редактировать, удалять активности.
- Перетаскивать блоки активностей для изменения времени начала/окончания.
- Сохранять расписания в `localStorage` по ключу `time-tracker-schedules` (формат описан в `time-tracker-schedules.d.ts`).
- Загружать справочник рангов/категорий/типов активностей из `localStorage` по ключу `time-tracker-categories` (формат описан в `time-tracker-categories.d.ts`).

### 2. Загрузка и инициализация

- При открытии страницы код проверяет `localStorage` по ключу `time-tracker-categories`.
  - Если данные есть и являются валидным JSON (согласно структуре `time-tracker-categories.d.ts`), они загружаются и используются.
  - Если данных нет или они невалидны – отображается блок с ошибкой конфигурации, работа страницы блокируется.
- Также из `localStorage` загружаются расписания по ключу `time-tracker-schedules` (если есть). Если нет – создаётся пустой корневой объект расписаний.
- Текущая выбранная дата – сегодняшняя (YYYY-MM-DD). Пользователь может переключать даты через календарь.
- При загрузке страницы отображаются:
  - временная шкала (00:00 – 24:00) с сеткой и метками времени;
  - блоки активностей для выбранной даты;
  - легенда с рангами, категориями и их цветами.

### 3. Структура справочных данных

Полное описание полей `ranks`, `categories`, `activity_types` и их типов содержится в файле деклараций TypeScript:  
[`time-tracker-categories.d.ts`](./time-tracker-categories.d.ts)

При построении UI страница группирует категории по полю `rank_id`, а типы активностей – по полю `category_id`. Цвет категории определяется следующим образом: если у категории есть собственное поле `color` – используется оно, иначе – цвет родительского ранга.

### 4. Формат расписаний

Полное описание полей `SchedulesRoot`, `ScheduleEntry`, `DaySchedule`, `ActivityEntry` содержится в файле деклараций TypeScript:  
[`time-tracker-schedules.d.ts`](./time-tracker-schedules.d.ts)

Обязательное условие для каждой активности: `delta === active + interruptBreaks + distractionBreaks`.

### 5. Временная шкала и блоки активностей

- Шкала расположена слева и идёт сверху вниз. Высота шкалы = 1440 пикселей (1 минута = 1 пиксель). На шкале отображаются метки каждого часа и тонкие деления каждые 5 минут.
- Блок активности:
  - Верхняя граница = `start` (минут от полуночи) в пикселях.
  - Высота = `delta` (минут) в пикселях.
  - Цвет фона: цвет категории (с учётом наследования от ранга).
  - Цвет текста – контрастный (чёрный или белый, вычисляется динамически).
  - Отображается: время начала и окончания (преобразованные в `HH:MM`), дельта (в часах:минутах), название активности (из справочника по `activityTypeId`), комментарий (если есть).
- Статус активности визуализируется:
  - `done` – полупрозрачный, серая гамма, галочка.
  - `in_progress` – пунктирная рамка.
  - `planned` – обычный вид.
- Если активности накладываются друг на друга (их временные интервалы пересекаются), то та активность, которая начинается позже (при одинаковом начале – та, у которой больше `id`), сдвигается вправо. Ширина всех блоков фиксирована – 500 пикселей. При сдвиге блок может выйти за пределы контейнера – контейнер расширяется по горизонтали для отображения всех колонок. У контейнера с блоками не должно быть полос прокрутки; полосы прокрутки (горизонтальная и вертикальная) появляются у всей страницы, если содержимое не помещается в окно браузера.

### 6. Перетаскивание блоков

- Перетаскивание блока (зажатие левой кнопки мыши или касание на сенсорном экране и движение вверх/вниз) изменяет время начала и окончания активности.
- Изменение времени выполняется с шагом 5 минут.
- При перетаскивании блок визуально следует за курсором (например, с полупрозрачностью или тенью).
- После отпускания блока новые значения `start` и `end` сохраняются в расписании, пересчитывается `delta`, блок перерисовывается на новом месте, данные сохраняются в `localStorage`.

### 7. Редактирование активностей

- **Двойной клик** по блоку открывает модальное окно редактирования.
- Модальное окно содержит:
  - Выбор ранга (загружается из справочника).
  - Выбор категории (зависит от выбранного ранга).
  - Выбор типа активности (зависит от выбранной категории).
  - Поле комментария.
  - Радиокнопки статуса.
  - Поля «Дельта», «Активное время», «Прерывательные перерывы», «Неопределённые перерывы».
  - Поля «Начало» и «Конец» в формате `HH:MM` (при сохранении преобразуются в минуты).
  - Кнопки «Начать» (установить начало сейчас), «Сделано» (установить конец сейчас и пересчитать дельту), «Сохранить», «Удалить» (при редактировании).
- **Валидация**: перед сохранением проверяется выполнение условия `delta === active + interruptBreaks + distractionBreaks`. При нарушении открывается модальное окно с вариантами автоматического исправления (например, скорректировать `delta`, `active` или `interruptBreaks`/`distractionBreaks`).

### 8. Легенда

- Отображаются все ранги из справочника.
- Для каждого ранга – список его категорий.
- Цвет: для ранга – `rank.color`, для категории – `category.color` (если есть) или цвет ранга.
- Отображается коэффициент ранга (`coefficient`).

### 9. Управление расписаниями

- Переключение дат через календарь (input `type="date"`). При выборе даты, если расписание отсутствует, создаётся новое с пустым массивом активностей.
- Редактор JSON: текстовое поле внизу страницы отображает **текущее расписание выбранного дня** (объект `DaySchedule` – массив `activities`, без обёртки `schedule` и без поля `date`). Пользователь может изменить JSON вручную и нажать кнопку «Применить». При применении:
  - Введённый JSON парсится и проверяется на соответствие структуре `DaySchedule` (массив активностей, каждая активность соответствует `ActivityEntry`).
  - Если валидация успешна, расписание выбранного дня заменяется на новое, а поле `current_datetime` корневого объекта обновляется текущим временем.
  - Данные сохраняются в `localStorage`, таблица перерисовывается.
  - Если JSON невалиден – выводится сообщение об ошибке, изменения не применяются.
- При любом изменении расписания (добавление, удаление, редактирование активности, перетаскивание блока, импорт через JSON) необходимо обновить поле `current_datetime` в корневом объекте `SchedulesRoot` на текущую дату и время в формате ISO 8601 с часовым поясом (например, `"2026-06-06T14:30:00+03:00"`). Это поле сохраняется в `localStorage` вместе с массивом `schedules`.


### 10. Технические требования

- Страница работает полностью на клиенте (HTML/CSS/JS), без серверных запросов.
- Статические стили (CSS) вынесены в один или несколько файлов (на усмотрение разработчика). В HTML-файле присутствуют только ссылки на эти файлы через `<link rel="stylesheet">`. Динамические стили (цвет фона блоков и т.п.) устанавливаются через JavaScript.
- JavaScript-код может быть организован в несколько файлов для удобства разработки и сопровождения (решение о количестве файлов принимает разработчик).
- Оформление страницы – светлое, без переключения тем.
- Размеры страницы фиксированы под большой экран. Если содержимое не помещается в окно браузера, у страницы появляются горизонтальная и вертикальная полосы прокрутки. Адаптивная вёрстка (резиновость, переносы) не требуется.
