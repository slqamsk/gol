# time-tracker-pages-spec.md

## 1. Введение. Общие технические требования для всех страниц

- Обе страницы работают полностью на клиенте (HTML/CSS/JS), без серверных запросов.
- Все данные хранятся в `localStorage`:
  - справочник активностей – по ключу `time-tracker-categories` (структура соответствует `TimeTrackerData` из `time-tracker.d.ts`);
  - расписания – по ключу `time-tracker-schedules` (структура соответствует `SchedulesRoot` из `time-tracker.d.ts`).
- При отсутствии или невалидности обязательных данных страницы должны показывать понятное сообщение об ошибке и (при необходимости) блокировать основной функционал.
- Статические стили (CSS) выносятся во внешние файлы (один или несколько). В HTML-файлах присутствуют только ссылки на эти файлы через `<link rel="stylesheet">`. Динамические стили (цвет фона, положение блоков и т.п.) устанавливаются через JavaScript.
- JavaScript-код может быть организован в несколько файлов для удобства разработки и сопровождения (решение о количестве файлов принимает разработчик). Для страницы редактора цветов требуется обязательное разделение: `color-data.js` (массив цветов палитры) и `editor.js` (основная логика). Для страницы дневного трекера такого обязательного разделения нет.
- Оформление обеих страниц – светлое, без переключения тем.
- Вёрстка рассчитана на большой экран; при нехватке места появляются горизонтальная и вертикальная полосы прокрутки у всей страницы (адаптивная «резиновая» вёрстка не требуется).

## 2. Редактор цветов справочника (`time-tracker-categories-editor.html`)

### 2.1 Назначение

Страница позволяет:
- **Вставить** содержимое файла `time-tracker-categories.json` в текстовое поле и сохранить его в `localStorage` браузера.
- **Просматривать** иерархию «ранги – категории» с визуальным отображением цветов.
- **Выбирать и менять** цвета для рангов и категорий через интерактивную палитру.

Все изменения автоматически сохраняются в `localStorage` и отображаются в текстовом поле JSON.

### 2.2 Загрузка и сохранение данных (только через вставку)

- При открытии страницы код проверяет `localStorage` по ключу `time-tracker-categories`.
  - Если данные есть и являются валидным JSON (содержат массив `ranks`), они загружаются, отображаются в текстовом поле и используются для построения таблицы.
  - Если данных нет или они невалидны, текстовое поле пустое, таблица пуста (или показывает надпись «Нет данных»). Пользователь должен вставить JSON вручную.
- Пользователь **вручную вставляет** содержимое JSON в текстовое поле (никакой кнопки «Загрузить файл» нет).
- По нажатию кнопки **«Применить»** страница парсит содержимое текстового поля. При успехе:
  - данные заменяют текущую структуру в памяти;
  - сохраняются в `localStorage`;
  - перерисовывается таблица;
  - в отдельном поле статуса появляется зелёное сообщение: «Данные применены».
- При ошибке (невалидный JSON, отсутствие массива `ranks`) – красное сообщение с описанием ошибки. Таблица и сохранённые данные не меняются.

### 2.3 Построение иерархии для отображения

- Исходные данные имеют плоскую структуру: корневые массивы `ranks` и `categories`.
- Для построения таблицы страница группирует категории по полю `rank_id`. Для каждого ранга формируется список категорий, у которых `category.rank_id === rank.id`.
- Редактирование цветов происходит непосредственно в плоских массивах (`ranks` и `categories`). При сохранении структура остаётся плоской (никакие вложенные массивы не создаются).

### 2.4 Отображение таблицы

Таблица состоит из двух колонок: **Ранги** и **Категории**.

#### 2.4.1 Ячейка ранга

- Содержит `id. Название ранга` (например, `1. Творческие`).
- Показывает английское имя цвета (например, `DarkOrchid`) и **русское название цвета** (например, «Тёмная орхидея»).
- Фон ячейки равен значению `rank.color` (поле `color` у ранга обязательно).

#### 2.4.2 Ячейка категории

- Содержит `id. Название категории`.
- **Если у категории есть собственное поле `color`**:
  - Фон ячейки равен этому цвету.
  - В подписи показываются английское имя и русское название цвета.
- **Если у категории нет поля `color`**:
  - Фон ячейки равен цвету **родительского ранга**.
  - **В подписи не показывается никакой информации о цвете** – только `id. Название категории`.
  - Поле `color` в JSON не создаётся.

#### 2.4.3 Объединение строк для ранга

- Для каждого ранга, у которого есть хотя бы одна категория, ячейка ранга в первой колонке должна занимать **столько строк, сколько категорий у этого ранга** (атрибут `rowspan`).
- Если у ранга нет категорий, ячейка ранга занимает одну строку, а во второй колонке отображается текст «Нет категорий» (или ячейка остаётся пустой).
- Объединение строк выполняется только при рендеринге таблицы; исходные данные при этом не изменяются.

#### 2.4.4 Стилизация таблицы

- Таблица должна быть **не шире содержимого** (ширина автоматическая, без принудительного растяжения на 100% родителя).
- Таблица должна выравниваться **по центру страницы** (например, через `margin: 0 auto` для таблицы или через flex-контейнер).
- Нужно задать минимальную ширину колонок, чтобы избежать слишком узких ячеек: 300px.
- Все ячейки таблицы (как заголовки, так и обычные) должны иметь **одинаковые границы** (border) одинаковой толщины и стиля.
- Цвет границы – чёрный.
- Границы должны быть сплошными (`solid`) и тонкими.

#### 2.4.5 Открытие модального окна

- При клике на любую ячейку (ранг или категория) открывается модальное окно выбора цвета.

### 2.5 Выбор цвета через палитру

- Модальное окно содержит сгруппированную таблицу стандартных именованных цветов CSS (английское имя, русское название). Каждая строка имеет фон, соответствующий цвету.
- При клике на строку палитры:
  - Выбранное английское имя цвета сохраняется:
    - Для **ранга** – в поле `rank.color` (обязательное поле, перезаписывается).
    - Для **категории** – **добавляется** поле `category.color` (если его не было).
  - Обновляются внутренние данные (плоские массивы), текстовое поле JSON, перерисовывается таблица.
  - Данные сохраняются в `localStorage`.
  - В поле статуса выводится зелёное сообщение: **«Цвет успешно изменён для ранга „Название ранга“»** или **«Цвет успешно изменён для категории „Название категории“»**.
  - Модальное окно закрывается.
- В палитре предусмотрена **опция «Сбросить (убрать собственный цвет)»** только для категорий (отдельная кнопка или пункт). При её выборе:
  - Если у категории есть собственное поле `color`, оно **удаляется** из объекта категории.
  - Категория снова отображается с цветом родительского ранга, а в подписи пропадает информация о цвете (остаётся только `id. Название`).
  - Изменения сохраняются в JSON (поле `color` исчезает), в `localStorage` и в текстовом поле.
  - Для ранга такой опции нет, так как цвет ранга обязателен.
- Допускается, чтобы один и тот же цвет (например, `Red`, `Gray`, `Blue` и т.д.) присутствовал в нескольких группах палитры (например, и в «Основные цвета», и в «Красные тона», и в «Серые тона»). Это не является ошибкой и упрощает поиск.

### 2.6 Управление сообщениями (статус)

- На странице есть **отдельное поле (блок) для сообщений** (например, `<div id="status-box">`).
- Сообщение появляется в этом поле и **остаётся там до тех пор, пока не будет заменено другим сообщением** (не исчезает автоматически).
- Цвет сообщения:
  - **зелёный** – успешная операция (применение JSON, изменение цвета);
  - **красный** – ошибка (невалидный JSON, отсутствие `ranks`).
- При успешном применении JSON выводится: «Данные применены».
- При успешном изменении цвета: «Цвет успешно изменён для ранга „X“» или «Цвет успешно изменён для категории „Y“».
- Каждое новое сообщение полностью заменяет предыдущее.

### 2.7 Технические замечания (специфичные для редактора)

- Палитра использует только стандартные именованные цвета CSS. В JSON сохраняется именно английское имя цвета (например, `"DarkOrchid"`).
- Код страницы **не должен** изменять массивы `activity_types` и объект `_service_context` – они остаются нетронутыми.
- При любых операциях с цветами структура JSON остаётся корректной: корневые массивы `ranks`, `categories`, `activity_types` сохраняются плоскими.
- Пользователь (человек-редактор) может свободно изменять текстовое поле вручную – страница только реагирует на нажатие «Применить» и на клики по ячейкам таблицы.
- JavaScript-код **обязательно** разделяется на:
  - `color-data.js` – содержит только массив `COLOR_GROUPS` (или аналогичную структуру с цветами палитры, их русскими названиями и HEX-кодами).
  - `editor.js` – основной код приложения: загрузка/сохранение localStorage, рендер таблицы, обработка кликов, модальное окно и т.д.
- В HTML-файле должны быть подключены все JS-файлы в правильном порядке.

## 3. Дневной трекер (`time-tracker.html`)

### 3.1 Назначение

Страница позволяет:
- Отслеживать активности пользователя в течение дня с визуализацией на временной шкале.
- Создавать, редактировать, удалять активности.
- Перетаскивать блоки активностей для изменения времени начала/окончания.
- Сохранять расписания в `localStorage` по ключу `time-tracker-schedules` (формат описан в `time-tracker.d.ts`).
- Загружать справочник рангов/категорий/типов активностей из `localStorage` по ключу `time-tracker-categories` (формат описан в `time-tracker.d.ts`).

### 3.2 Загрузка и инициализация

- При открытии страницы код проверяет `localStorage` по ключу `time-tracker-categories`.
  - Если данные есть и являются валидным JSON (согласно структуре `time-tracker.d.ts`), они загружаются и используются.
  - Если данных нет или они невалидны – отображается блок с ошибкой конфигурации, работа страницы блокируется.
- Также из `localStorage` загружаются расписания по ключу `time-tracker-schedules` (если есть). Если нет – создаётся пустой корневой объект расписаний.
- Текущая выбранная дата – сегодняшняя (YYYY-MM-DD). Пользователь может переключать даты через календарь.
- При загрузке страницы отображаются:
  - временная шкала (00:00 – 24:00) с сеткой и метками времени;
  - блоки активностей для выбранной даты;
  - легенда с рангами, категориями и их цветами.

### 3.3 Структура справочных данных

Полное описание полей `ranks`, `categories`, `activity_types` и их типов содержится в файле деклараций TypeScript: [`time-tracker.d.ts`](./time-tracker.d.ts)

При построении UI страница группирует категории по полю `rank_id`, а типы активностей – по полю `category_id`. Цвет категории определяется следующим образом: если у категории есть собственное поле `color` – используется оно, иначе – цвет родительского ранга.

### 3.4 Формат расписаний

Полное описание полей `SchedulesRoot`, `ScheduleEntry`, `DaySchedule`, `ActivityEntry` содержится в файле деклараций TypeScript: [`time-tracker.d.ts`](./time-tracker.d.ts)

Обязательное условие для каждой активности: `delta === active + interruptBreaks + distractionBreaks`.

### 3.5 Временная шкала и блоки активностей

- Шкала расположена слева и идёт сверху вниз. Высота шкалы = 1440 пикселей (1 минута = 1 пиксель). На шкале отображаются метки каждого часа и тонкие деления каждые 5 минут.
- Блок активности:
  - Верхняя граница = `start` (минут от полуночи) в пикселях.
  - Высота = `delta` (минут) в пикселях.
  - Цвет фона: цвет категории (с учётом наследования от ранга).
  - Цвет текста – контрастный (чёрный или белый, вычисляется динамически).
  - Отображается: время начала и окончания (преобразованные в `HH:MM`), дельта (в часах:минутах), название активности (из справочника по `activityTypeId`), комментарий (если есть).
- Статус активности визуализируется:
  - `done` – полупрозрачный, серая гамма, галочка.
  - `in_progress` – пунктирная рамка.
  - `planned` – обычный вид.
- Если активности накладываются друг на друга (их временные интервалы пересекаются), то та активность, которая начинается позже (при одинаковом начале – та, у которой больше `id`), сдвигается вправо. Ширина всех блоков фиксирована – 500 пикселей. При сдвиге блок может выйти за пределы контейнера – контейнер расширяется по горизонтали для отображения всех колонок. У контейнера с блоками не должно быть полос прокрутки; полосы прокрутки (горизонтальная и вертикальная) появляются у всей страницы, если содержимое не помещается в окно браузера.

### 3.6 Перетаскивание блоков

- Перетаскивание блока (зажатие левой кнопки мыши или касание на сенсорном экране и движение вверх/вниз) изменяет время начала и окончания активности.
- Изменение времени выполняется с шагом 5 минут.
- При перетаскивании блок визуально следует за курсором (например, с полупрозрачностью или тенью).
- После отпускания блока новые значения `start` и `end` сохраняются в расписании, пересчитывается `delta`, блок перерисовывается на новом месте, данные сохраняются в `localStorage`.

### 3.7 Редактирование активностей

- **Двойной клик** по блоку открывает модальное окно редактирования.
- Модальное окно содержит:
  - Выбор ранга (загружается из справочника).
  - Выбор категории (зависит от выбранного ранга).
  - Выбор типа активности (зависит от выбранной категории).
  - Поле комментария.
  - Радиокнопки статуса.
  - Поля «Дельта», «Активное время», «Прерывательные перерывы», «Неопределённые перерывы».
  - Поля «Начало» и «Конец» в формате `HH:MM` (при сохранении преобразуются в минуты).
  - Кнопки «Начать» (установить начало сейчас), «Сделано» (установить конец сейчас и пересчитать дельту), «Сохранить», «Удалить» (при редактировании).
- **Валидация**: перед сохранением проверяется выполнение условия `delta === active + interruptBreaks + distractionBreaks`. При нарушении открывается модальное окно с вариантами автоматического исправления (например, скорректировать `delta`, `active` или `interruptBreaks`/`distractionBreaks`).

### 3.8 Легенда

- Отображаются все ранги из справочника.
- Для каждого ранга – список его категорий.
- Цвет: для ранга – `rank.color`, для категории – `category.color` (если есть) или цвет ранга.
- Отображается коэффициент ранга (`coefficient`).

### 3.9 Управление расписаниями

- Переключение дат через календарь (input `type="date"`). При выборе даты, если расписание отсутствует, создаётся новое с пустым массивом активностей.
- Редактор JSON: текстовое поле внизу страницы отображает **текущее расписание выбранного дня** (объект `DaySchedule` – массив `activities`, без обёртки `schedule` и без поля `date`). Пользователь может изменить JSON вручную и нажать кнопку «Применить». При применении:
  - Введённый JSON парсится и проверяется на соответствие структуре `DaySchedule` (массив активностей, каждая активность соответствует `ActivityEntry`).
  - Если валидация успешна, расписание выбранного дня заменяется на новое, а поле `current_datetime` корневого объекта обновляется текущим временем.
  - Данные сохраняются в `localStorage`, таблица перерисовывается.
  - Если JSON невалиден – выводится сообщение об ошибке, изменения не применяются.
- При любом изменении расписания (добавление, удаление, редактирование активности, перетаскивание блока, импорт через JSON) необходимо обновить поле `current_datetime` в корневом объекте `SchedulesRoot` на текущую дату и время в формате ISO 8601 с часовым поясом (например, `"2026-06-06T14:30:00+03:00"`). Это поле сохраняется в `localStorage` вместе с массивом `schedules`.

### 3.10 Технические требования (специфичные для трекера)

- Оформление страницы – светлое, без переключения тем.
- Размеры страницы фиксированы под большой экран. Если содержимое не помещается в окно браузера, у страницы появляются горизонтальная и вертикальная полосы прокрутки. Адаптивная вёрстка (резиновость, переносы) не требуется.
- Статические стили (CSS) вынесены в один или несколько файлов (на усмотрение разработчика). В HTML-файле присутствуют только ссылки на эти файлы через `<link rel="stylesheet">`.
- JavaScript-код может быть организован в несколько файлов для удобства разработки и сопровождения (решение о количестве файлов принимает разработчик).
