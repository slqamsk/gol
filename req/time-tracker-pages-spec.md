# GOL - Gamification of life - Требования к страницам
Имя файла: `time-tracker-pages-spec.md`

## 01. Введение. Общие технические требования для всех страниц

**FR.01.01.** Все страницы работают полностью на клиенте (HTML/CSS/JS), без серверных запросов.

**FR.01.01.01.** Все данные хранятся в `localStorage`:
Ключ: `time-tracker-categories` - справочник активностей – структура соответствует `TimeTrackerData`.
Ключ: `time-tracker-schedules` - расписания – структура соответствует `SchedulesRoot`.

**FR.01.01.02.** При отсутствии или невалидности обязательных данных страницы должны показывать понятное сообщение об ошибке и (при необходимости) блокировать основной функционал.

**FR.01.01.03.** Статические стили (CSS) выносятся во внешние файлы. Для всех страниц используется общий файл `main.css` (содержит базовую стилизацию, общие классы, таблицы, модальные окна и т.п.). В HTML-файлах присутствуют только ссылки на этот файл через `<link rel="stylesheet">`. Динамические стили (цвет фона, положение блоков и т.п.) устанавливаются через JavaScript.

**FR.01.01.04.** JavaScript-код может быть организован в несколько файлов для удобства разработки и сопровождения (решение о количестве файлов принимает разработчик). Для страницы редактора цветов требуется обязательное разделение: `color-data.js` (массив цветов палитры) и `editor.js` (основная логика). Для страницы дневного трекера такого обязательного разделения нет.

**FR.01.01.05.** Оформление обеих страниц – светлое, без переключения тем.

**FR.01.01.06.** Вёрстка рассчитана на большой экран; при нехватке места появляются горизонтальная и вертикальная полосы прокрутки у всей страницы (адаптивная «резиновая» вёрстка не требуется).

## 02. Главная страница (`index.html`)

### 02.01. Назначение

**FR.02.01.** Страница выполняет роль информационного портала и единой точки входа в систему Time Tracker. Она содержит общее описание методологии геймификации жизни, правила работы с учётом времени и ссылки на функциональные страницы приложения.

### 02.02. Структура и содержимое

**FR.02.02.01.** Страница должна включать:
- **FR.02.02.01.01.** Заголовок и краткое описание проекта «Геймификация жизни».
- **FR.02.02.01.02.** Основные правила расчёта баланса дня (формула, весовые коэффициенты, ставки) – выжимка из `_service_context` справочника.
- **FR.02.02.01.03.** Рекомендации по использованию: как создавать активности, как интерпретировать статусы, как работают перерывы.
- **FR.02.02.01.04.** Навигационное меню со ссылками на следующие страницы:
  - Редактор справочника (`time-tracker-categories-editor.html`) – для просмотра и изменения цветов рангов и категорий.
  - Основной трекер (`time-tracker.html`) – для планирования дня, учёта активностей и визуализации временной шкалы.
  - Загрузка и выгрузка расписаний – описание того, что в основном трекере есть встроенный JSON-редактор, который позволяет экспортировать/импортировать расписание текущего дня, а также ссылка на раздел «Управление расписаниями» в `time-tracker.html`.
  - Архивация расписаний – пояснение, что все расписания автоматически хранятся в `localStorage` и могут быть скопированы через JSON-редактор или сохранены вручную; дополнительная страница для пакетной архивации не предусмотрена, но пользователь может сохранить резервную копию через инструменты разработчика браузера.

**FR.02.02.02.** Для удобства навигации каждая ссылка должна открываться в той же вкладке (без `target="_blank"`).

### 02.03. Стилизация

**FR.02.03.01.** Страница использует общий файл стилей `main.css`, в котором определены:
- Базовые стили для body, заголовков, текста, ссылок.
- Карточки или сетка для описания правил и ссылок.
- Адаптивное поведение (при необходимости) – но основной упор на большой экран.

**FR.02.03.02.** Дополнительные стили для `index.html` могут быть размещены в том же `main.css` (через селекторы, специфичные для этой страницы) или вынесены в отдельный файл (на усмотрение разработчика), но требование выноса всех статических стилей во внешние файлы остаётся в силе.

## 03. Редактор цветов справочника (`time-tracker-categories-editor.html`)

### 03.01. Назначение

**FR.03.01.** Страница позволяет:
- **FR.03.01.01.** **Вставить** содержимое файла `time-tracker-categories.json` в текстовое поле и сохранить его в `localStorage` браузера.
- **FR.03.01.02.** **Просматривать** иерархию «ранги – категории» с визуальным отображением цветов.
- **FR.03.01.03.** **Выбирать и менять** цвета для рангов и категорий через интерактивную палитру.

**FR.03.01.04.** Все изменения автоматически сохраняются в `localStorage` и отображаются в текстовом поле JSON.

### 03.02. Загрузка и сохранение данных (только через вставку)

**FR.03.02.01.** При открытии страницы код проверяет `localStorage` по ключу `time-tracker-categories`.
- **FR.03.02.01.01.** Если данные есть и являются валидным JSON (содержат массив `ranks`), они загружаются, отображаются в текстовом поле и используются для построения таблицы.
- **FR.03.02.01.02.** Если данных нет или они невалидны, текстовое поле пустое, таблица пуста (или показывает надпись «Нет данных»). Пользователь должен вставить JSON вручную.

**FR.03.02.02.** Пользователь **вручную вставляет** содержимое JSON в текстовое поле (никакой кнопки «Загрузить файл» нет).

**FR.03.02.03.** По нажатию кнопки **«Применить»** страница парсит содержимое текстового поля. При успехе:
- **FR.03.02.03.01.** данные заменяют текущую структуру в памяти;
- **FR.03.02.03.02.** сохраняются в `localStorage`;
- **FR.03.02.03.03.** перерисовывается таблица;
- **FR.03.02.03.04.** в отдельном поле статуса появляется зелёное сообщение: «Данные применены».

**FR.03.02.04.** При ошибке (невалидный JSON, отсутствие массива `ranks`) – красное сообщение с описанием ошибки. Таблица и сохранённые данные не меняются.

### 03.03. Построение иерархии для отображения

**FR.03.03.01.** Исходные данные имеют плоскую структуру: корневые массивы `ranks` и `categories`.

**FR.03.03.02.** Для построения таблицы страница группирует категории по полю `rank_id`. Для каждого ранга формируется список категорий, у которых `category.rank_id === rank.id`.

**FR.03.03.03.** Редактирование цветов происходит непосредственно в плоских массивах (`ranks` и `categories`). При сохранении структура остаётся плоской (никакие вложенные массивы не создаются).

### 03.04. Отображение таблицы

**FR.03.04.01.** Таблица состоит из двух колонок: **Ранги** и **Категории**.

#### 03.04.01. Ячейка ранга

**FR.03.04.02.** Ячейка ранга:
- **FR.03.04.02.01.** Содержит `id. Название ранга` (например, `1. Творческие`).
- **FR.03.04.02.02.** Показывает английское имя цвета (например, `DarkOrchid`) и **русское название цвета** (например, «Тёмная орхидея»).
- **FR.03.04.02.03.** Фон ячейки равен значению `rank.color` (поле `color` у ранга обязательно).

#### 03.04.02. Ячейка категории

**FR.03.04.03.** Ячейка категории:
- **FR.03.04.03.01.** Содержит `id. Название категории`.
- **FR.03.04.03.02.** **Если у категории есть собственное поле `color`**:
  - **FR.03.04.03.02.01.** Фон ячейки равен этому цвету.
  - **FR.03.04.03.02.02.** В подписи показываются английское имя и русское название цвета.
- **FR.03.04.03.03.** **Если у категории нет поля `color`**:
  - **FR.03.04.03.03.01.** Фон ячейки равен цвету **родительского ранга**.
  - **FR.03.04.03.03.02.** **В подписи не показывается никакой информации о цвете** – только `id. Название категории`.
  - **FR.03.04.03.03.03.** Поле `color` в JSON не создаётся.

#### 03.04.03. Объединение строк для ранга

**FR.03.04.04.** Для каждого ранга, у которого есть хотя бы одна категория, ячейка ранга в первой колонке должна занимать **столько строк, сколько категорий у этого ранга** (атрибут `rowspan`).

**FR.03.04.05.** Если у ранга нет категорий, ячейка ранга занимает одну строку, а во второй колонке отображается текст «Нет категорий» (или ячейка остаётся пустой).

**FR.03.04.06.** Объединение строк выполняется только при рендеринге таблицы; исходные данные при этом не изменяются.

#### 03.04.04. Стилизация таблицы

**FR.03.04.07.** Таблица должна быть **не шире содержимого** (ширина автоматическая, без принудительного растяжения на 100% родителя).

**FR.03.04.08.** Таблица должна выравниваться **по центру страницы** (например, через `margin: 0 auto` для таблицы или через flex-контейнер).

**FR.03.04.09.** Нужно задать минимальную ширину колонок, чтобы избежать слишком узких ячеек: 300px.

**FR.03.04.10.** Все ячейки таблицы (как заголовки, так и обычные) должны иметь **одинаковые границы** (border) одинаковой толщины и стиля.

**FR.03.04.11.** Цвет границы – чёрный.

**FR.03.04.12.** Границы должны быть сплошными (`solid`) и тонкими.

#### 03.04.05. Открытие модального окна

**FR.03.04.13.** При клике на любую ячейку (ранг или категория) открывается модальное окно выбора цвета.

### 03.05. Выбор цвета через палитру

**FR.03.05.01.** Модальное окно содержит сгруппированную таблицу стандартных именованных цветов CSS (английское имя, русское название). Каждая строка имеет фон, соответствующий цвету.

**FR.03.05.02.** При клике на строку палитры:
- **FR.03.05.02.01.** Выбранное английское имя цвета сохраняется:
  - **FR.03.05.02.01.01.** Для **ранга** – в поле `rank.color` (обязательное поле, перезаписывается).
  - **FR.03.05.02.01.02.** Для **категории** – **добавляется** поле `category.color` (если его не было).
- **FR.03.05.02.02.** Обновляются внутренние данные (плоские массивы), текстовое поле JSON, перерисовывается таблица.
- **FR.03.05.02.03.** Данные сохраняются в `localStorage`.
- **FR.03.05.02.04.** В поле статуса выводится зелёное сообщение: **«Цвет успешно изменён для ранга „Название ранга“»** или **«Цвет успешно изменён для категории „Название категории“»**.
- **FR.03.05.02.05.** Модальное окно закрывается.

**FR.03.05.03.** В палитре предусмотрена **опция «Сбросить (убрать собственный цвет)»** только для категорий (отдельная кнопка или пункт). При её выборе:
- **FR.03.05.03.01.** Если у категории есть собственное поле `color`, оно **удаляется** из объекта категории.
- **FR.03.05.03.02.** Категория снова отображается с цветом родительского ранга, а в подписи пропадает информация о цвете (остаётся только `id. Название`).
- **FR.03.05.03.03.** Изменения сохраняются в JSON (поле `color` исчезает), в `localStorage` и в текстовом поле.
- **FR.03.05.03.04.** Для ранга такой опции нет, так как цвет ранга обязателен.

**FR.03.05.04.** Допускается, чтобы один и тот же цвет (например, `Red`, `Gray`, `Blue` и т.д.) присутствовал в нескольких группах палитры (например, и в «Основные цвета», и в «Красные тона», и в «Серые тона»). Это не является ошибкой и упрощает поиск.

### 03.06. Управление сообщениями (статус)

**FR.03.06.01.** На странице есть **отдельное поле (блок) для сообщений** (например, `<div id="status-box">`).

**FR.03.06.02.** Сообщение появляется в этом поле и **остаётся там до тех пор, пока не будет заменено другим сообщением** (не исчезает автоматически).

**FR.03.06.03.** Цвет сообщения:
- **FR.03.06.03.01.** **зелёный** – успешная операция (применение JSON, изменение цвета);
- **FR.03.06.03.02.** **красный** – ошибка (невалидный JSON, отсутствие `ranks`).

**FR.03.06.04.** При успешном применении JSON выводится: «Данные применены».

**FR.03.06.05.** При успешном изменении цвета: «Цвет успешно изменён для ранга „X“» или «Цвет успешно изменён для категории „Y“».

**FR.03.06.06.** Каждое новое сообщение полностью заменяет предыдущее.

### 03.07. Технические замечания (специфичные для редактора)

**FR.03.07.01.** Палитра использует только стандартные именованные цвета CSS. В JSON сохраняется именно английское имя цвета (например, `"DarkOrchid"`).

**FR.03.07.02.** Код страницы **не должен** изменять массивы `activity_types` и объект `_service_context` – они остаются нетронутыми.

**FR.03.07.03.** При любых операциях с цветами структура JSON остаётся корректной: корневые массивы `ranks`, `categories`, `activity_types` сохраняются плоскими.

**FR.03.07.04.** Пользователь (человек-редактор) может свободно изменять текстовое поле вручную – страница только реагирует на нажатие «Применить» и на клики по ячейкам таблицы.

**FR.03.07.05.** JavaScript-код **обязательно** разделяется на:
- **FR.03.07.05.01.** `color-data.js` – содержит только массив `COLOR_GROUPS` (или аналогичную структуру с цветами палитры, их русскими названиями и HEX-кодами).
- **FR.03.07.05.02.** `editor.js` – основной код приложения: загрузка/сохранение localStorage, рендер таблицы, обработка кликов, модальное окно и т.д.

**FR.03.07.06.** В HTML-файле должны быть подключены все JS-файлы в правильном порядке.

## 04. Дневной трекер (`time-tracker.html`)

### 04.01. Назначение

**FR.04.01.** Страница позволяет:
- **FR.04.01.01.** Отслеживать активности пользователя в течение дня с визуализацией на временной шкале.
- **FR.04.01.02.** Создавать, редактировать, удалять активности.
- **FR.04.01.03.** Перетаскивать блоки активностей для изменения времени начала/окончания.
- **FR.04.01.04.** Сохранять расписания в `localStorage` по ключу `time-tracker-schedules` (формат описан в `time-tracker.d.ts`).
- **FR.04.01.05.** Загружать справочник рангов/категорий/типов активностей из `localStorage` по ключу `time-tracker-categories` (формат описан в `time-tracker.d.ts`).

### 04.02. Загрузка и инициализация

**FR.04.02.01.** При открытии страницы код проверяет `localStorage` по ключу `time-tracker-categories`.
- **FR.04.02.01.01.** Если данные есть и являются валидным JSON (согласно структуре `time-tracker.d.ts`), они загружаются и используются.
- **FR.04.02.01.02.** Если данных нет или они невалидны – отображается блок с ошибкой конфигурации, работа страницы блокируется.

**FR.04.02.02.** Также из `localStorage` загружаются расписания по ключу `time-tracker-schedules` (если есть). Если нет – создаётся пустой корневой объект расписаний.

**FR.04.02.03.** Текущая выбранная дата – сегодняшняя (YYYY-MM-DD). Пользователь может переключать даты через календарь.

**FR.04.02.04.** При загрузке страницы отображаются:
- **FR.04.02.04.01.** временная шкала (00:00 – 24:00) с сеткой и метками времени;
- **FR.04.02.04.02.** блоки активностей для выбранной даты;
- **FR.04.02.04.03.** легенда с рангами, категориями и их цветами.

### 04.03. Структура справочных данных

**FR.04.03.01.** Полное описание полей `ranks`, `categories`, `activity_types` и их типов содержится в файле деклараций TypeScript: [`time-tracker.d.ts`](./time-tracker.d.ts)

**FR.04.03.02.** При построении UI страница группирует категории по полю `rank_id`, а типы активностей – по полю `category_id`. Цвет категории определяется следующим образом: если у категории есть собственное поле `color` – используется оно, иначе – цвет родительского ранга.

### 04.04. Формат расписаний

**FR.04.04.01.** Полное описание полей `SchedulesRoot`, `ScheduleEntry`, `DaySchedule`, `ActivityEntry` содержится в файле деклараций TypeScript: [`time-tracker.d.ts`](./time-tracker.d.ts)

**FR.04.04.02.** Обязательное условие для каждой активности: `delta === active + interruptBreaks + distractionBreaks`.

### 04.05. Временная шкала и блоки активностей

**FR.04.05.01.** Шкала расположена слева и идёт сверху вниз. Высота шкалы = 1440 пикселей (1 минута = 1 пиксель). На шкале отображаются метки каждого часа и тонкие деления каждые 5 минут.

**FR.04.05.02.** Блок активности:
- **FR.04.05.02.01.** Верхняя граница = `start` (минут от полуночи) в пикселях.
- **FR.04.05.02.02.** Высота = `delta` (минут) в пикселях.
- **FR.04.05.02.03.** Цвет фона: цвет категории (с учётом наследования от ранга).
- **FR.04.05.02.04.** Цвет текста – контрастный (чёрный или белый, вычисляется динамически).
- **FR.04.05.02.05.** Отображается: время начала и окончания (преобразованные в `HH:MM`), дельта (в часах:минутах), название активности (из справочника по `activityTypeId`), комментарий (если есть).

**FR.04.05.03.** Статус активности визуализируется:
- **FR.04.05.03.01.** `done` – полупрозрачный, серая гамма, галочка.
- **FR.04.05.03.02.** `in_progress` – пунктирная рамка.
- **FR.04.05.03.03.** `planned` – обычный вид.

**FR.04.05.04.** Если активности накладываются друг на друга (их временные интервалы пересекаются), то та активность, которая начинается позже (при одинаковом начале – та, у которой больше `id`), сдвигается вправо. Ширина всех блоков фиксирована – 500 пикселей. При сдвиге блок может выйти за пределы контейнера – контейнер расширяется по горизонтали для отображения всех колонок. У контейнера с блоками не должно быть полос прокрутки; полосы прокрутки (горизонтальная и вертикальная) появляются у всей страницы, если содержимое не помещается в окно браузера.

### 04.06. Перетаскивание блоков

**FR.04.06.01.** Перетаскивание блока (зажатие левой кнопки мыши или касание на сенсорном экране и движение вверх/вниз) изменяет время начала и окончания активности.

**FR.04.06.02.** Изменение времени выполняется с шагом 5 минут.

**FR.04.06.03.** При перетаскивании блок визуально следует за курсором (например, с полупрозрачностью или тенью).

**FR.04.06.04.** После отпускания блока новые значения `start` и `end` сохраняются в расписании, пересчитывается `delta`, блок перерисовывается на новом месте, данные сохраняются в `localStorage`.

### 04.07. Редактирование активностей

**FR.04.07.01.** **Двойной клик** по блоку открывает модальное окно редактирования.

**FR.04.07.02.** Модальное окно содержит:
- **FR.04.07.02.01.** Выбор ранга (загружается из справочника).
- **FR.04.07.02.02.** Выбор категории (зависит от выбранного ранга).
- **FR.04.07.02.03.** Выбор типа активности (зависит от выбранной категории).
- **FR.04.07.02.04.** Поле комментария.
- **FR.04.07.02.05.** Радиокнопки статуса.
- **FR.04.07.02.06.** Поля «Дельта», «Активное время», «Прерывательные перерывы», «Неопределённые перерывы».
- **FR.04.07.02.07.** Поля «Начало» и «Конец» в формате `HH:MM` (при сохранении преобразуются в минуты).
- **FR.04.07.02.08.** Кнопки «Начать» (установить начало сейчас), «Сделано» (установить конец сейчас и пересчитать дельту), «Сохранить», «Удалить» (при редактировании).

**FR.04.07.03.** **Валидация**: перед сохранением проверяется выполнение условия `delta === active + interruptBreaks + distractionBreaks`. При нарушении открывается модальное окно с вариантами автоматического исправления (например, скорректировать `delta`, `active` или `interruptBreaks`/`distractionBreaks`).

### 04.08. Легенда

**FR.04.08.01.** Отображаются все ранги из справочника.

**FR.04.08.02.** Для каждого ранга – список его категорий.

**FR.04.08.03.** Цвет: для ранга – `rank.color`, для категории – `category.color` (если есть) или цвет ранга.

**FR.04.08.04.** Отображается коэффициент ранга (`coefficient`).

### 04.09. Управление расписаниями

**FR.04.09.01.** Переключение дат через календарь (input `type="date"`). При выборе даты, если расписание отсутствует, создаётся новое с пустым массивом активностей.

**FR.04.09.02.** Редактор JSON: текстовое поле внизу страницы отображает **текущее расписание выбранного дня** (объект `DaySchedule` – массив `activities`, без обёртки `schedule` и без поля `date`). Пользователь может изменить JSON вручную и нажать кнопку «Применить». При применении:
- **FR.04.09.02.01.** Введённый JSON парсится и проверяется на соответствие структуре `DaySchedule` (массив активностей, каждая активность соответствует `ActivityEntry`).
- **FR.04.09.02.02.** Если валидация успешна, расписание выбранного дня заменяется на новое, а поле `current_datetime` корневого объекта обновляется текущим временем.
- **FR.04.09.02.03.** Данные сохраняются в `localStorage`, таблица перерисовывается.
- **FR.04.09.02.04.** Если JSON невалиден – выводится сообщение об ошибке, изменения не применяются.

**FR.04.09.03.** При любом изменении расписания (добавление, удаление, редактирование активности, перетаскивание блока, импорт через JSON) необходимо обновить поле `current_datetime` в корневом объекте `SchedulesRoot` на текущую дату и время в формате ISO 8601 с часовым поясом (например, `"2026-06-06T14:30:00+03:00"`). Это поле сохраняется в `localStorage` вместе с массивом `schedules`.

### 04.10. Технические требования (специфичные для трекера)

**FR.04.10.01.** Оформление страницы – светлое, без переключения тем.

**FR.04.10.02.** Размеры страницы фиксированы под большой экран. Если содержимое не помещается в окно браузера, у страницы появляются горизонтальная и вертикальная полосы прокрутки. Адаптивная вёрстка (резиновость, переносы) не требуется.

**FR.04.10.03.** Статические стили (CSS) вынесены в один или несколько файлов (на усмотрение разработчика). В HTML-файле присутствуют только ссылки на эти файлы через `<link rel="stylesheet">`.

**FR.04.10.04.** JavaScript-код может быть организован в несколько файлов для удобства разработки и сопровождения (решение о количестве файлов принимает разработчик).
